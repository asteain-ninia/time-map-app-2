# テスト問題点メモ

## ManageLayersUseCase に関する検証漏れ
- 階層検証失敗時のテスト (`tests/application/manageLayersUseCase.test.js`)
  ```js
  it("throws when layer hierarchy validation fails on add", async () => {
    layerService.validateLayerHierarchy.mockReturnValueOnce(false);

    await expect(useCase.addLayer("Invalid")).rejects.toThrow("Layer hierarchy validation failed");
    expect(worldRepository.saveWorld).not.toHaveBeenCalled();
  });

  it("does not save when reordered layers break hierarchy", async () => {
    world.layers.push(new Layer("layer-1", "Overlay", 1, true, 1.0));
    world.layers.push(new Layer("layer-2", "Top", 2, true, 1.0));
    layerService.validateLayerHierarchy.mockReturnValueOnce(false);

    await expect(useCase.reorderLayer("layer-2", 0)).rejects.toThrow("Layer hierarchy validation failed");
    expect(worldRepository.saveWorld).not.toHaveBeenCalled();
  });
  ```
  例外と `saveWorld` 呼び出しの有無のみをチェックしており、`world.layers` の件数や順序が汚れていないかを確認していない。失敗後に配列が変化してもテストは合格する。

- 実装側の状態変更 (`src/application/usecases/ManageLayersUseCase.js`)
  ```js
  world.layers.push(newLayer);
  const isValid = this._layerService.validateLayerHierarchy(world.layers);
  if (!isValid) {
    throw new Error("Layer hierarchy validation failed");
  }
  ```
  ```js
  world.layers = updatedLayers;
  const isValid = this._layerService.validateLayerHierarchy(world.layers);
  if (!isValid) {
    throw new Error("Layer hierarchy validation failed");
  }
  ```
  検証前に `world.layers` を直接書き換えており、失敗時にロールバックする処理が存在しない。テストではレイヤー数・順序が変わっていないことを明示的に確認しないと、既知の不具合を見逃す。

## プレゼンテーション層のプライベート依存
- 内部ヘルパーを直接呼び出すテスト (`tests/presentation/mapViewRendererHelper.test.js`)
  ```js
  const result = helper._unwrapLongitudeSequence(sequence);
  ```
  `_unwrapLongitudeSequence` はアンダースコア付きの内部ヘルパーであり、公開 API ではない。メソッド名や公開範囲をリファクタリングすると、機能仕様に変化がなくてもテストが壊れる。

- 該当メソッドの定義 (`src/presentation/views/map/MapViewRendererHelper.js`)
  ```js
  _unwrapLongitudeSequence(points) {
    if (!Array.isArray(points) || points.length === 0) {
      return [];
    }
    const result = [{ x: points[0].x, y: points[0].y }];
    let previousLongitude = points[0].x;
    let wrapOffset = 0;
    ...
  }
  ```
  private 的に扱われているヘルパーで、テストから直接参照する設計になっていない。公開メソッド経由で描画結果や座標列を検証するテストに置き換える必要がある。

- Facade の内部フィールドへ依存するテスト (`tests/presentation/viewModels.test.js`)
  ```js
  const worldRepository = {
    getWorld: vi.fn(async () => createWorld()),
    saveWorld: vi.fn(async () => {})
  };
  const editFeatureUseCase = { _worldRepository: worldRepository };
  ```
  `EditFeatureUseCase` の内部フィールド `_worldRepository` を直接 stub 化しており、Facade の実装詳細に縛られている。イベント通知や公開メソッドの戻り値で挙動を検証する作りにしないと、内部構造の変更でテストが壊れる。

- Facade 内部の該当フィールド (`src/application/usecases/EditFeatureUseCase.js`)
  ```js
  constructor(worldRepository, geometryService, layerService, polygonEditService, idGenerationService) {
    this._worldRepository = worldRepository;
    ...
  }
  ```
  `_worldRepository` は内部状態として保持されているだけで、外部から直接差し替える契約は存在しない。テスト側が無理に触れると保守性が低下する。

## EditFeatureUseCase の実装詳細依存
- 委譲先を直接差し替えるテスト (`tests/application/editFeatureUseCase.test.js`)
  ```js
  const useCase = new EditFeatureUseCase(
    worldRepository,
    geometryService,
    layerService,
    polygonEditService,
    idService
  );

  useCase._addFeatureUseCase = { execute: vi.fn().mockResolvedValue({ id: "added" }) };
  useCase._updateFeatureUseCase = { execute: vi.fn().mockResolvedValue({ id: "feature-1", name: "Updated" }) };
  useCase._deleteFeatureUseCase = { execute: vi.fn().mockResolvedValue(undefined) };
  useCase._vertexEditUseCase = { moveVertices: vi.fn().mockResolvedValue({ updated: true }) };
  ```
  非公開フィールドに直接アクセスして委譲の呼び出し回数だけを確認している。Facade の内部構成が変わった場合に即座にテストが失敗する。

- Facade が依存を自前で生成している実装 (`src/application/usecases/EditFeatureUseCase.js`)
  ```js
  this._addFeatureUseCase = new AddFeatureUseCase(
    worldRepository, geometryService, layerService,
    this._generateIdFunc, this._processGeometryFunc, this._getVerticesFromIdsFunc
  );
  this._updateFeatureUseCase = new UpdateFeatureUseCase(
    worldRepository, geometryService, layerService,
    this._processGeometryFunc, this._getVerticesFromIdsFunc,
    polygonEditService
  );
  this._deleteFeatureUseCase = new DeleteFeatureUseCase(
    worldRepository,
    this._cleanupUnusedVerticesFunc
  );
  this._vertexEditUseCase = new VertexEditUseCase(
    worldRepository, geometryService,
    this._cleanupUnusedVerticesFunc,
    this._generateIdFunc, this._getOlderVertexIdFunc,
    layerService
  );
  ```
  委譲先を内部で new しているため、テストは公開 API を通じて結果を検証するか、依存差し替え用の仕組みを設計として用意しない限り保守性が担保できない。
